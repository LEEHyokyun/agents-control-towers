# Rough Architecture

1. 기술·패턴·인터페이스·계층·추상화 자체를 목적으로 추가하지 않으며, 반드시 실제 문제와 변경 이유가 있어야 한다.
2. 객체는 책임과 변경 이유를 기준으로 판단하며, 서로 다른 책임·변경 이유·의존성이 섞인 경우에만 분리를 검토한다.
3. 중복은 동일한 책임·정책의 반복인지 확인하며, 단순히 코드가 비슷하다는 이유로 추상화하거나 통합하지 않는다.
4. 변경된 구조가 기존 설계와 충돌하거나 불필요한 복잡성을 증가시키는지 판단한다.
5. 개선 가능성만으로 문제를 만들지 말고, 위 원칙의 명백한 위반만 문제로 판단한다.
