# Boilerplate and Duplication Principles

## 1. Boilerplate의 정의

반복되는 코드가 존재한다는 이유만으로
모두 제거하지 않는다.

먼저 반복의 성격을 확인한다.

```text
문법적 반복
의미적 반복
비즈니스 규칙의 반복
우연한 유사성
```

각각의 해결 방법은 다르다.

---

# 2. 동일 코드와 동일 책임은 다르다

두 코드가 현재 동일하게 보이더라도
변경 이유가 다르다면 동일한 책임이라고 판단하지 않는다.

예:

```text
A의 validation
B의 validation
```

코드가 비슷하다는 이유로 하나의 Validator로 통합하지 않는다.

먼저 동일한 비즈니스 규칙인지 확인한다.

---

# 3. 중복 제거 기준

중복을 제거할 가치가 높은 경우:

- 동일한 비즈니스 규칙
- 동일한 변경 이유
- 동일한 정책
- 동일한 불변조건
- 수정 시 항상 함께 변경되는 코드

중복을 유지할 수 있는 경우:

- 우연히 현재 구현이 비슷하다.
- 변경 이유가 다르다.
- 향후 변경 방향이 다르다.
- 추상화하면 서로 다른 책임이 결합된다.

---

# 4. Boilerplate 판단

다음과 같은 반복이 발견되면 개선 가능성을 검토한다.

- 반복적인 변환 코드
- 동일한 예외 처리
- 동일한 로깅 구조
- 동일한 설정 코드
- 동일한 검증 코드
- 동일한 인프라 접근 코드

그러나 공통화가 새로운 결합을 만든다면
현재 반복을 유지할 수 있다.

---

# 5. 보일러플레이트 제거의 목표

목표는 코드 줄 수를 줄이는 것이 아니다.

목표는 다음과 같다.

```text
불필요한 반복 감소
+
변경 지점 감소
+
의미 명확화
+
책임 응집도 향상
```

코드가 짧아졌지만 이해하기 어려워졌다면
보일러플레이트 제거가 성공했다고 판단하지 않는다.

---

# 6. Utility Class 주의

공통 기능을 하나의 Utility Class에 계속 추가하지 않는다.

다음과 같은 문제가 발생하는지 확인한다.

```text
무관한 기능 증가
↓
Utility 의존성 증가
↓
변경 영향 범위 증가
↓
God Utility
```

공통 기능이 실제로 하나의 개념이나 책임을 공유하는지 확인한다.
